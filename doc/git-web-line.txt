1. git-web-line.nvim                          *git-web-line-git-web-line.nvim*

**Navigate your code in Neovim, share it on GitHub, GitLab, Bitbucket or
SourceHut instantly.**

`git-web-line.nvim` is a lightweight Neovim plugin designed to streamline the
process of sharing specific parts of your code. Perfect for code reviews or
when you’re exploring a new codebase, this plugin lets you generate a GitHub
URL for the current line in your Neovim editor, opening it directly in the
browser. Say goodbye to the tedious process of navigating through GitHub’s
web UI to share a piece of code!

This project is not only a handy tool for developers but also serves as a
personal learning journey into Lua and Neovim plugin development.


FEATURES                             *git-web-line-git-web-line.nvim-features*

- **Quick Link Generation:** Instantly get a sharable GitHub link for the line you’re on in Neovim.
- **Seamless Integration:** Works within your Neovim workflow, making code sharing as simple as a command execution.
- **Speeds Up Reviews:** Ideal for code reviews, saving time and enhancing productivity.


REQUIREMENTS                     *git-web-line-git-web-line.nvim-requirements*

- Neovim >= 0.10
- `git` on your `$PATH`

Run `:checkhealth git-web-line` to verify your setup.

      'robgyiv/git-web-line.nvim',
      cmd = 'GitWebLine',
      opts = {},

USAGE                                   *git-web-line-git-web-line.nvim-usage*

1. Navigate to the line in a file you want to share, or select lines in visual mode.
2. Run `:GitWebLine`, or `:GitWebLine <remote>` to link to a specific remote (remote names tab-complete).
3. Your default web browser will open the page with that line or range highlighted.

  -----------------------------------------------------------------------
  Command                             Result
  ----------------------------------- -----------------------------------
  :GitWebLine                         Open the current line

  :'<,'>GitWebLine                    Open the selected lines (also works
                                      with any range,
                                      e.g. :10,20GitWebLine)

  :GitWebLine!                        Copy the URL to the clipboard
                                      instead of opening it

  :GitWebLine upstream                Use the upstream remote
  -----------------------------------------------------------------------
`:GitWebLine!` is handy over SSH, where there’s no local browser to open;
Neovim 0.10+ copies to your local clipboard through OSC 52 when the terminal
supports it. Without a clipboard provider, the URL goes to the unnamed
register.

On GitHub, markdown and other rendered formats (reStructuredText, AsciiDoc,
Org, Textile) are linked with `?plain=1` so that line anchors work.

Supported hosts are GitHub, GitLab (including self-hosted instances with
`gitlab` in the domain), Bitbucket and SourceHut. Unknown hosts use
GitHub-style URLs. SSH (`git@host:owner/repo`, `ssh://`) and HTTPS remotes are
supported, with or without a `.git` suffix. File paths and branch names are
percent-encoded, so spaces and special characters are safe.


CHOOSING A REMOTE ~

When no remote is passed to the command, the first match of the following is
used:

1. The `remote` option passed to `setup()`
2. The remote the current branch tracks (its upstream)
3. `origin`
4. The first configured remote


UNPUSHED CHANGES ~

Before opening the browser, the plugin compares your local state with the
remote’s remote-tracking refs (e.g. `origin/main`) and reports when:

- the remote has no fetched refs (it has never been fetched, or the repository may not exist)
- the current branch has not been pushed, or has commits that aren’t pushed
- the file doesn’t exist on the remote
- the file has uncommitted or unsaved changes

These checks don’t touch the network, so they are only as current as your
last `git fetch`. The `on_unpushed` option controls what happens next (see
below).


CONFIGURATION                   *git-web-line-git-web-line.nvim-configuration*

Calling `setup()` is optional. The defaults are:

>lua
    require('git-web-line').setup({
      -- Remote to link to. nil picks one automatically (see "Choosing a remote").
      remote = nil,
      -- What to do when the branch, commits or file aren't pushed to the remote:
      --   'warn'      notify, then open the branch URL anyway
      --   'abort'     notify with an error and don't open anything
      --   'permalink' link to the newest pushed commit instead of the branch
      on_unpushed = 'warn',
      -- What to do with the URL: 'open' it in the browser, 'copy' it to the
      -- clipboard, or 'both'. `:GitWebLine!` always copies.
      action = 'open',
    })
<
